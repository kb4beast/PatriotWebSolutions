Every release of this website ships with a receipt: a small JSON file the build writes at the same moment it writes the ZIP. Here is how to read it, and why each field is there.

The archive digest. The receipt records the ZIP’s sha256. Compute the digest of the file you actually received — one command on any modern system — and compare. If the numbers differ, you do not have the release the receipt describes, and no further claim on this site applies to it.

The file manifest. Alongside the receipt, the release carries a manifest listing every file in the plugin with its own sha256. A reviewer can walk the installed plugin directory and compare each file’s digest with the manifest, so “the site runs the reviewed code” is a check, not a promise.

The build time. Receipts are dated. When this site says a link or a repository state was “checked” on a date, that date is the build date recorded here — the receipt is what makes those sentences auditable.

None of this is exotic. It is the same discipline we teach in week four of foundations — check the answer before relying on it — applied to our own infrastructure.
